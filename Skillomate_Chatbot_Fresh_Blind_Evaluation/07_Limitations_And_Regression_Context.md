# Limitations and regression context

This evaluation does not authorize deployment. Its release gate uses the unchanged rubric: at least 90% overall and in every functional category, complete authorization/course-isolation compliance, no critical safety failure, full literal fidelity for correctly selected approved assets, and no regression among previously passing cases. Passing these gates would qualify a candidate only for further end-to-end verification.

No external AI inference is authorized in this task. Model-dependent behavior is untested when the provider cannot execute. A fallback response is retained as evidence, but it is not substituted for a live model response. Provider retry attempts blocked by the local guard are recorded separately from actual external requests. Internal repair activity can only be counted where the application exposes telemetry; absence of a flag is not evidence that no internal repair code ran.

Synthetic identities exercise actual local authentication and entitlement logic, while database operations are served by controlled memory-only models. There is no production MongoDB, billing service, real learner data, browser UI or external-provider end-to-end coverage. Positive subscriptions represent verified synthetic access; they do not establish the behavior of production subscription records. Courses and user IDs used in traces are synthetic.

Fresh-context agents followed allowlisted inputs on a shared filesystem. There is no OS-enforced per-agent filesystem sandbox. Input hashes, attestations and preserved initial drafts support procedural separation; they cannot independently prove every read made by an agent. Independent AI grading is not a human panel. Frozen expected outcomes and literal body checks reduce implementation-derived grading bias.

The earlier course-isolation review reported 38 isolation checks, 514 chatbot checks and 167 Python evaluator checks passing. Its full-backend run reported 1045 passes and 24 existing failures out of 1069; the same 24 failed before the correction. Its recorded Phase 12 comparison covered 40 previously passing cases/48 turns without response changes. These are historical review results, not newly executed blind cases or live-provider coverage. The prior report and its hashes are retained by the candidate preservation manifest; none of those results is added to the 120-case blind denominator.

The original exposed Phase 14B cases and rubric are preserved. No stopped evaluation is resumed or rebranded. Exposed failures remain known regression cases and are not counted as new blind evidence. The present evaluation makes no new claim that the full backend suites or recorded regressions were rerun: the implementation is frozen and the user requested a new evaluation, not another implementation change. Final integrity evidence checks candidate, tests, assets, evaluator, prior archives, local configuration hashes and Git index against the pre-execution baseline.

The question set remains useful if execution stops, but unexecuted cases cannot substantiate a claim about the candidate. Any case exposed during this evaluation must be treated as known in later work. A later blind evaluation requires a newly authored frozen set rather than rerunning this set as independent.

Coverage inventory: the frozen set uses two published synthetic courses plus an unknown selector, global subscription fixtures (active/inactive/expired), and four authentication rejection modes. It has no purchase-only or limited-trial entitlement case and no same-conversation transition between two explicit distinct course selectors. Cross-course requests/comparison and ownership inspection are covered, but this is not the full course-switching adversarial matrix. No cases were added or rewritten after execution to fill those gaps. See `evidence/coverage_inventory.json`.

The VM application modules receive a synthetic JWT signing configuration and the configured provider fields. This is an isolated local harness rather than the full production application entry point/environment. Other production environment flags and deployment configuration behavior are outside this evaluation. Model request bodies, selected models and errors are retained; transport headers/credentials are deliberately excluded. The blocked adapter evidence does not include a per-attempt destination URL, so it is not a wire-level network capture. The guard denies all external destinations regardless.
