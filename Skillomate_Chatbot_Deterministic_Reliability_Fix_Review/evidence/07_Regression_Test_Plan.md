# Regression-test plan

This is a proposed plan, not a report of new passing suites. This investigation ran guarded pure-helper diagnostics only: 63/63 recorded local product-rule failure responses were reproduced exactly. That confirms failure mechanisms and does not establish any fix. Existing application tests and the Python evaluator were not modified or rerun for this read-only review.

## Offline contracts

| Contract | Required positive assertions | Negative controls and evidence |
|---|---|---|
| Authorization and ownership | Authorized same-course records and complete approved assets remain available; user/course/conversation identifiers stay server scoped | Invalid JWT, missing user, expired session, inactive entitlement, forged selector, missing/ambiguous course, purchase-only and limited trial; explicit same-session course changes and cross-course comparison. Inspect every retrieved source and complete assembled payload before any adapter call. Preserve both earlier exposed isolation failures as known regressions. |
| Exact-copy and fill | All 19 source assets; several independent affirmative copy forms per asset; raw-copy leaves every bracket and byte intact; fill changes only explicitly approved slots | Explanation, negated copy, original generation, product names containing troubleshooting words, archive/text-diff references, absent attributes. Independent literal oracle from approved source plus allowlisted substitutions; do not call the renderer to construct expected results. Verify every full body, never substring-only success. |
| Entity and attributes | Straight/curly quotes, name-first/object-first declarations, English/Hindi/Hinglish, punctuation, exact Unicode, separately supplied object/material/colour/price | Request phrases beginning for/of, recolour clauses, quoted instructions and label metadata must not become names. Unknown facts remain unknown; reject unsafe names using all existing controls, including NFKC view, mixed-script/bidi checks and injection rejection. |
| Typed operations/state | Declare, rename, correct, replace, recolour, task-only follow-up; active/passive and multilingual equivalents | Assert the initial product, material and price really entered state before switching. After replacement old product-bound facts must disappear; explicit unresolved replacement must clarify without silently using the prior identity. Recolour never changes identity. Rename policy distinguishes same item from a new item. |
| Session lifecycle | Recognized seeded facts survive an allowed follow-up, disappear on explicit reset/new conversation and remain actor scoped | Verify actual saved state and history, not just final wording. Exercise no-ID legacy behavior against the documented API contract, empty IDs, delete scope, forged client history and schema-v2 non-resurrection. The original SR-002/003/004 controls did not seed recognized structured identities. |
| Request planning | Educational explanation, exact source, fill, novel scene/dialogue/caption, workflow and decision requests receive distinct plans | Quoted paid/order/plan/name words must not trigger unrelated account summaries; camera angle must not become ad angle. Compound tasks declare every deliverable. Negated hooks/copy must not generate those outputs. Real personal billing/profile requests still work. |
| Language/count | Explicit response language wins over product-name script; original name preserved; separate dialogue/source language; explicit hook count | English requests with Hindi names, Hindi prose with English approved bodies, Hinglish corrections, requested short Hindi dialogue, counts with adjectives. Validate genuine output obligations without forcing name repetition in every generic FAQ. |
| Local completeness | Local FAQ/draft is terminal only when it answers the actual task; known product slots applied; instructions/constraints retained | Incomplete guidance routes to generation or a clear clarification/unavailable notice. Preserve accurate short FAQ answers. Safety refusal is a separate terminal contract, not forced through creative completeness repair. |
| Adapter accounting | Injected local denial, timeout, rate limit, malformed reply, scope rejection, repair success/failure | Typed policy denial must not masquerade as a live provider outage. Bound retries/repairs; distinguish attempted, transmitted, generated and accepted outputs. Exact templates should need zero inference. No offline test sends content externally. |

Extend relevant existing files after implementation approval: `tests/product-tutor-phase14a.test.cjs`, `product-tutor-unicode-safety.test.cjs`, the phase3/5/7/9/11 and quality product-tutor suites, `tutor-knowledge.test.cjs`, `tutor-course-isolation.test.cjs`, `ai-chat-history.test.cjs` and `mobile-course-ai-cache.test.cjs`. Use `tests/ai-tutor-fixture.cjs` for synthetic records, with separately documented gaps in query/Mongoose behavior. Add an isolated local-database contract run if authentic query semantics are needed; do not connect to production.

Each family needs fresh paraphrases and negative controls independent of the 67 exposed cases. The exposed cases may be regression diagnostics; they cannot serve as another blind evaluation. Preserve approved-source hashes, existing API response shapes, Unicode safety and other-course/platform behavior.

## Execution and acceptance

First demonstrate each targeted failing assertion against the frozen baseline, then implement a small patch and run the targeted family. Run relevant course-isolation and safety gates before broader functional evaluation. Stop for a critical safety/authorization failure and preserve evidence. No question-specific answer patches are acceptable.

For a later authorized implementation, the broad backend command is `node --test tests/*.test.cjs` from `edunex-b`, after checking external/DB boundaries and applying a network-denial guard. `npm run test:ai` covers only history and knowledge and is not the full backend suite. Run the existing evaluator with `python3 -m unittest discover -s tests -p 'test_product_evaluator*.py'`; retain the existing v7 implementation and thresholds. Capture exit codes, all failures/skips/timeouts, test counts, environment flags and provider-attempt accounting. These commands are instructions for future work, not claims they ran in this review.

Replay the four Phase 14A cases, Unicode safety cases, course-isolation cases and all 40 previously passing Phase 12 recorded-response comparisons using the existing evidence/oracles. Recorded-response comparisons establish deterministic preservation only; no fixture counts as live generation. Every changed answer needs old/new text, route, fact/state delta and adjudication, including acceptable intentional changes. Existing baseline failures must remain visible rather than silently excluded.

Release criteria stay as frozen: at least 90% overall and each functional category, 100% authorization/isolation, zero critical safety failures, 100% exact-body fidelity for correctly selected assets and no regression in previously passing cases. Keep PASS/FAIL/UNTESTED and ambiguous items separate, with all planned cases visible. Do not calculate a new accuracy from helper replays or this audit. Genuine semantic generation, grounding repair, latency and output quality require the separately approved live plan, followed by a genuinely new independently authored evaluation.
