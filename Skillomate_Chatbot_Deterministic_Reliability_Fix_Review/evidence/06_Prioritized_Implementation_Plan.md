The request plan is transient: `{mode, targetAsset, outputs:[{kind,count,language}], explanationLanguage, constraints, operations, confidence}`. Product facts carry exact display name, supplied object/attributes, explicit negatives and evidence spans; security-normalized text is a separate validation view. An adapter should retain the existing productContext schema/API initially. Do not introduce a model-based extractor, new persistence architecture or database migration as the first fix.

A shared response contract must check local and model origins, while retaining terminal security refusals. It should not demand name repetition in a generic correct explanation. Exact source rendering has its own literal transformation oracle; semantic teaching/generation has a different contract. Do not reuse the faulty renderer as its own correctness oracle.

Allowed slot semantics need explicit product review. Missing non-PRODUCT fields are confirmed capability gaps against the learner requests, but not proof that the earlier narrowly scoped fixes promised every arbitrary placeholder. Review the existing PRODUCT-only model guard before adding an allowlisted schema for other approved fields. No approved source wording may change.

Prefer small reviewable patches in this dependency order, each with negative controls and a changed-file manifest. Broad regex exceptions and question-specific canned answers are excluded. Preserve authentication/entitlement/course guards at every new boundary. Global routing/language changes have cross-course risk; constrain initial disambiguation to verified product-course requests and run platform/other-course controls.

Offline work can establish route selection, full-body copying, typed extraction/state, language/count rules, scope checks, negative controls, injected retry behavior and schema compatibility. It cannot establish natural model response quality, token billing, latency, finish-reason behavior, grounding repair effectiveness or provider availability. These require the separately approved plan in report 08.

Rollback for any later local patch should reverse only that patch against the recorded working-tree baseline and rerun the targeted invariants. Do not reset, stash, discard unrelated changes, toggle authorization off or edit production configuration. No deployment/commit/push is proposed. All accuracy claims require new executed tests; these exposed cases are diagnostic regressions, not a reusable blind set.
