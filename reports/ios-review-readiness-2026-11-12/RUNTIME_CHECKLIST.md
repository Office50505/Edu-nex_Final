# Exact-build runtime and submission gates

All cases below are **NOT_RUN_ON_BUILD_35** in this audit. Source/unit evidence is not substituted for these cases. Use TestFlight sandbox and an authorized disposable test account. Record test date, tester, build/version/artifact/source commit, deployed backend commit, device/OS/storefront, expected/actual result and evidence for every case. Do not copy passwords or real user payloads into reports.

| ID | Required cases and acceptance evidence |
|---|---|
| R01 | Identify processed 1.0 (35), IPA/archive hash and source/build logs; prove the tested and submitted artifacts match. Confirm matched backend/website commits, provider model and disclosure fingerprint. |
| R02 | Physical iPhone fresh install/launch, update from previous release, foreground/background, relaunch, offline startup and session restore. No crashes, hangs, prototype text or hidden QA behavior. Record the launch and typical flow on the physical device as requested by Apple. |
| R03 | Guest Home/Courses/details and lesson lists without registration; protected media/notes/downloads stay denied. Explicit free content, if offered, is truly free. Exercise all guest exits and optional auth routes. Document account necessity for paid/account features and Apple's prior registration concern. |
| R04 | Sandbox product load and price in each enabled storefront; title, benefits, duration, renewal price, eligible/ineligible introductory offers, full recurring cost, links and cancellation terms before confirmation. Verify actual App Store offer configuration; never treat local .storekit prices/offers as proof. |
| R05 | Sandbox success, user cancel, pending/Ask to Buy, interrupted connection/app termination, duplicate taps and delayed verification. Grant access only after trusted server verification. No duplicate charge or stuck purchase UI. |
| R06 | Restore after reinstall/new supported device; correct app-account association, cross-account transaction denial and logout/account switch while requests are pending. Existing member playback succeeds; foreign/replayed/revoked transactions fail. Verify reviewer account and access without OTP obstruction. |
| R07 | Sandbox renewal, cancel-at-period-end, grace/billing retry, expiration, refund and revocation; deliver actual Apple server notifications, duplicate/out-of-order notification handling and transient Apple API failure recovery. Grace period currently configured for sandbox only: do not assume production grace. |
| R08 | Existing web/Android membership works under documented cross-platform design; avoid duplicate subscriptions, verify manage/refund support, decline purchase without losing previously purchased rights; no required sharing/reviews/contacts tasks. |
| R09 | First AI send with absent/current/old consent; unavailable endpoint fails closed; decline prevents provider transmission and preserves courses; acceptance records current disclosure/version; withdrawal blocks new calls. Exercise account switching, relaunch/reinstall and changed provider policy. Inspect controlled synthetic outbound payloads and retry/repair paths. Delete history locally/server-side independently from withdrawal. |
| R10 | Controlled AI/content moderation tests across supported languages: discriminatory/violent/sexual/minor exploitation, self-harm/dangerous advice, religious abuse, crisis profiteering and false claims; normal educational false positives. Report responses, confirm receipt and timely operator response. If user-to-user or creator content exists, verify blocking, filtering, reporting and age controls. Document 4.7 chatbot applicability. |
| R11 | Paid member course load/play/seek/fullscreen/speed/mute/next/back, progress save/retry, notes, downloads, offline playback, account isolation, disk-full handling, expiry/revocation, wishlist and certificates. Exercise both fresh and cached state. Offline media must be licensed and stored within authorized app containers. |
| R12 | Supported iPad orientations, split views/multitasking where offered, keyboard/safe areas and layouts, small/large iPhones, light/dark presentation; VoiceOver focus/labels, Dynamic Type and contrast. Test native controls and accessibility claims, not just source styling. |
| R13 | Minimum-supported and latest-supported physical OS; IPv6-only NAT64/DNS64, poor connectivity, transitions between Wi-Fi/cellular and offline. Playback interruption by calls/audio, lock/unlock and PiP/background transitions; memory, energy and thermal behavior. |
| R14 | Optional profile photo: picker cancel/denial and system selection, resizing/upload, invalid image/error recovery, replacement cleanup and default avatar. Confirm no contacts/GPS/mic/camera requirement for courses. Check Files/iCloud integration if generic file selection is offered. |
| R15 | Compare every enabled localization's description, screenshots, previews, header/search assets and paid-feature disclosures with actual 35. Validate age questionnaire, 13+ override/regional equivalents, name/keyword accuracy, fictional screenshot account data, image rights and absence of misleading income/AI/Apple claims. Check any events, preorders, promoted IAP or custom pages if configured. |
| R16 | Follow every in-app legal/support/account/resource link on each intended storefront, including redirects and subsequent Pricing/checkout navigation. Verify support contact, actual issue/report triage, privacy/terms rendering, subscription management and no disallowed purchase steering. Website payment presence alone is not a violation. |
| R17 | Owner supplies course/instructor/music/video/voice/model/portrait/artwork licences, commercial distribution/offline-download authorization, third-party tool terms and developer-to-operator authorization. Reconcile docs/IOS_CONTENT_RIGHTS_INVENTORY.md and actual listing/bundle. |
| R18 | Inspect exact signed archive: bundle/version/source provenance, minimum OS and SDK, public APIs, executable-download behavior, embedded SDK signatures/privacy manifests, required-reason API use, actual collection/linking/tracking, entitlements/background modes, export declaration, dSYM UUIDs and processing warnings. Confirm compatible iOS-on-Mac/visionOS availability separately if enabled. |
| R19 | Confirm enabled countries versus India phone registration, age collection/minimization and minor-user consent obligations; provider/subprocessor data retention/protection/deletion and cross-border processing. On disposable account test password/DELETE confirmation, active Apple subscription warning/manage link, immediate deletion, session revocation, photo/chat/progress removal, billing cleanup retry and disclosed retained/anonymized records/backups. |
| R20 | Re-read all active Apple messages and fulfil every requested item; finalize truthful notes and accessible physical recording/documents. Verify account contact/operator identity, agreements/tax/banking and trader/territory requirements where applicable. No coerced/fake reviews, discovery manipulation, unfair access restrictions or unsupported marketing claims. Record owner sign-off and resolve every matrix row before claiming ready. |

Apple's pre-submission checklist is also accounted for: crashes/bugs (R02/R11-R14), accurate metadata (R15/R20), reachable review contact (R16/R20), full reviewer access (R03/R06), live backend (R01/R09), detailed IAP/review explanations (R04/R20), applicable regulatory documents (R17/R19/R20), and relevant API/HIG/branding/privacy documentation for actual features (R12/R15/R18). General introductions and post-submission obligations require continued honest support and response handling, not a one-time automated pass.
